SendWhale exposes a set of developer APIs and integration surfaces that let you build on top of your email marketing workspace — from reading brand data in external tools to creating and sending campaigns programmatically. All API operations are scoped to a workspace, and the backend enforces row-level security (RLS) so a credential can only access data in workspaces you are authorized for.

## Available API surfaces

<Accordion title="Brand Context API">
  The Brand Context API is a read-only endpoint that returns your workspace's brand data — including name, description, voice guidelines, colors, fonts, social links, and knowledge base entries. Use it to give AI clients accurate, up-to-date brand context without manual copy-pasting.

  **Endpoint:** `POST https://fvtvyejucthdmnpfkrnl.supabase.co/functions/v1/brand-agent`

  Authenticate with a brand read key scoped to your workspace. Brand read keys expire after 90 days and cannot send mail, read contact lists, or modify campaigns.
</Accordion>

<Accordion title="Campaign API">
  The Campaign API lets you create and manage campaigns, templates, and audiences programmatically. Campaign operations are also available through the local MCP server tools, which provide the same functionality to AI clients that support the Model Context Protocol.
</Accordion>

<Accordion title="Transactional Email API">
  The Transactional Email API lets you send triggered, one-to-one emails from your application — for example, account alerts, receipts, or onboarding sequences. Credentials and endpoints for transactional email are configured separately from marketing credentials.

  <Info>Contact [support@gosendwhale.com](mailto:support@gosendwhale.com) to request access to the Transactional Email API.</Info>
</Accordion>

<Accordion title="Webhooks">
  Webhooks push event notifications to your server when campaign delivery events occur. Subscribe to events like `campaign.sent`, `campaign.delivered`, `campaign.bounced`, `campaign.clicked`, and `campaign.unsubscribed` to trigger downstream workflows in real time.
</Accordion>

<Accordion title="Local MCP server">
  The SendWhale MCP server runs as a local stdio server (powered by Deno) and connects AI clients — such as Claude Desktop — to your workspace via the Model Context Protocol. It exposes 11 tools, pre-built resources, and prompt templates that let an AI agent draft, review, and manage campaigns on your behalf.
</Accordion>

## Authentication modes

SendWhale supports four credential types depending on which API surface you are using.

| Credential type | Used for | Expiry |
|---|---|---|
| User JWT | Direct API calls authenticated as yourself | Session lifetime |
| Workspace API key | Campaign and contact operations | Configurable |
| Brand read key | Brand Context API (read-only) | 90 days |
| MCP access token (user JWT) | Local MCP server | Session lifetime |

All credentials must be passed as a `Bearer` token in the `Authorization` header. See the [Authentication](./authentication) page for full details on obtaining and rotating each credential type.

## Workspace scope

Every API request is scoped to a single workspace. Include your `workspace_id` in the request body or as a query parameter on every call. The backend uses Supabase row-level security to enforce data isolation — a credential cannot read or write data outside the workspaces it is authorized for, regardless of how the request is constructed.
